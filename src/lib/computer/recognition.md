# Circuit recognition and schematic identities

`recognition.ts` exports the component registry, bounded sync/async recognition, explicit port mappings, verification, and identity resolution. `Circuit.ports` orders switch/clock/pulse inputs and public lamp outputs. Circuits without this field keep their legacy all-terminal module interface. Internal lamps are never selected automatically by the recognition dialog.

`registerRecognitionComponent` accepts a total combinational function and ordered role labels. Tutorial truth specs register their full functions, including specs whose tutorial grading uses sample rows; recognition still enumerates every combination within its limits. The standalone registry includes gates, selectors, demultiplexers, a decoder, adders, and an explicitly defined highest-input-priority encoder. Return values distinguish equivalent, mismatch, invalid, and unsupported. Matching uses the chosen ordering without permutations; every surviving match includes its exact mapping. Counterexamples show the first differing row for each rejected candidate.

The checker evaluates the actual gate graph and ignores identity claims. It rejects undriven or multiply driven one-bit pins, unknown output pins, feedback, stateful parts, behavioral shortcuts, and four-valued buses. It does not turn Z/X into false. Stateful equivalence is unsupported: a future extension needs a reset contract and temporal specification, and must distinguish sequence evidence from exhaustive combinational equivalence. Current limits are eight inputs, 512 nested nodes, and 65,536 node evaluations. The asynchronous API yields every eight rows and accepts an AbortSignal.

`verifyCircuitIdentity` retains the implementation and attaches a claim only after exhaustive comparison. `verifiedCircuitIdentity` checks the current implementation and re-evaluates imported user claims. Built-in claims must match an implementation registered by the source catalog. Names, labels, positions, wire styles, and public input switch positions do not define identity. Structural edits, nesting edits, constants, behavior tags, and port ordering do. Cache keys contain the exact implementation rather than trusting the small persisted fingerprint. Copies remap explicit port IDs; parent module connections are remapped by terminal ID when an internal interface changes.

`GateSymbol` is the shared palette/canvas renderer. It accepts the circuit, not a name-based symbol guess. A verified user component uses the same SVG geometry as its built-in identity and adds an accessible Yours badge. Unknown modules retain their names in the surrounding builder and a generic module graphic.

Mux/demux graphics use familiar trapezoids and a select pin. Decoder/encoder graphics use binary/one-of-n roles; adders use Σ; storage uses data/output roles and clock-edge marks. Complex block graphics are project conventions, not claims of a single official universal symbol. Output inversion bubbles appear only for inverting gates. The app's decoder is active high, unlike the active-low outputs of TI's SN74HC138; copying those bubbles would misstate its behavior. Manufacturer references reviewed: [TI SN74HC157 datasheet](https://www.ti.com/lit/ds/symlink/sn74hc157.pdf), [TI SN74HC138 datasheet](https://www.ti.com/lit/ds/symlink/sn74hc138.pdf).
