# Seven-segment circuits

`sevenSegment.ts` supplies active-high raw display demos, `BCD_DECODER`, `ADD3`, `decimalConverter(width, digits)`, `decodedDisplayCircuit(digits)`, and decimal demos. `sevensegment` is a sink: pin `digit * 7 + segment` controls exactly one bar, with a–g indices 0–6. Digit 0 is units, followed by tens, hundreds and thousands. The SVG reads those signals directly and orders decimal places most significant on the left. Decimal point is not implemented.

Raw displays accept `digits: 1 | 2 | 3 | 4` (default 1). Place buttons expose one seven-pin bank and its wires at a time without changing stored connections. The same bank selection applies to drag targets and port-group wiring, including inside an unfolded module. Place selection is view state. Display-only modules are valid when they contain a raw seven-segment sink, even with no public output lamps.

BCD weights 1, 2, 4, 8 encode one decimal digit. Values 10–15 blank every segment. This differs from unsigned binary conversion: decimal converters retain the least-significant requested decimal digits, preserve leading zeroes, and assert their final OVERFLOW output when the input reaches `10 ** digits`. There is no saturation or implicit hexadecimal mode. `input4` stays 0–15, `input8` stays 0–255, and the separate `input14` source accepts 0–16383. Decimal entry rejects values outside those ranges.

The BCD decoder and add-three stage are total four-input functions synthesized into NOT, AND and OR circuits. The sum-of-products synthesizer covers only ON rows; a greedy cover selects size, not semantics. Binary conversion is combinational double dabble: fourteen or eight stages correct five decimal nibbles, then wire the next binary bit into units. The fifth nibble retains the ten-thousands bit for overflow through 16383. Shifts are wires, and correction modules contain real gates. No behavioral evaluator or JavaScript numeric shortcut runs these converters. Folded and unfolded simulation use the same circuit; the flattened netlist independently evaluates its gates.

A decoded display package accepts four BCD pins per place. Its folded screen reads the actual snapshots of its internal raw displays, guarded by the registered implementation identity. Enter or unfold it to inspect each digit decoder and every a–g wire. Editing the implementation invalidates that identity; it never substitutes new internals for a reader's construction.

`SevenSegment` is the shared raw SVG renderer. `GateSymbol` uses the existing decoder identity for verified converters. Optional tutorial levels cover raw wiring (128 combinations), BCD decoding (16), correction (16), binary conversion, and composition of all four digit counts. Eight-bit conversion grading checks every value; fourteen-bit and larger composition grading uses documented boundary/spread samples. Exhaustive recognition of fourteen-input circuits remains outside the recognition API's limits. Hints have no automatic trigger.

`/computer/seven-segment` starts with editable switches and a raw digit. The builder display palette offers raw, decoded, and converter components, with separate wired demos. Production keeps the existing development-only computer demo policy.
