# Input device circuit contracts

`buttonInputCircuit()` contains edge-clocked capture, a two-stage request synchronizer, and a separate two-stage held-level synchronizer. Outputs are CAPTURED EVENT, SAMPLED HOLD, REQUEST, in that order. Inputs are RAW BUTTON, SAMPLE CLOCK, ACKNOWLEDGE, RESET. All storage uses ordinary resettable DFFs and survives folding through existing nested snapshots.

A raw rising edge sets capture without a CPU clock. ACK or RESET clears it asynchronously with priority. REQUEST requires both synchronized capture and current capture, so stale synchronizer state cannot reassert an acknowledged request. Holding raw high does not create another capture after ACK. Multiple presses before acknowledgment coalesce. A press during ACK/RESET is ignored. These are ideal switch semantics; bounce, metastability, minimum pulse width and asynchronous reset recovery are not analog-simulated. SAMPLED HOLD may miss a brief press while CAPTURED remembers it.

`buttonCpuCircuit()` adapts only the input source of the existing CPU. REQUEST feeds the existing key register load and KEY READY next-state logic. The existing IN instruction asserts KEY_OUT and acknowledges capture. Its input reset also clears KEY READY, without aborting an interrupt already accepted. Full runtime reset restores the CPU, interface and transient controls. The input code is fixed at 1. Existing vector 02, INT_OPCODE, stack variants, IE masking and RETI remain unchanged. HALT is not an interrupt-wake instruction.

`compileButtonProgram()` opts out of the compiler's legacy implicit EI. Its source initializes shared variables then explicitly calls `interrupts_on()`. `compileProgram()` retains implicit EI by default, preserving existing programs and traces. The opt-in prevents early captured input from running a handler before globals initialize. The handler checker verifies two entry/IN/RETI sequences, outputs, and restored PC/SP/ACC/carry. It checks behavior, not source spelling.

`LockedClock.input()` sets transient manual button levels and records a simulation frame at the current CPU clock level. `cycle()` retains these levels. `reset()` releases them. This supports a complete raw pulse while the CPU is paused. Existing timeline snapshots and clock ownership remain per builder.

`matrixRowCircuit(columns)` models an isolated switch row using Boolean connectivity. ROW ACTIVE=1 means the electrical row driver sinks to 0. ROW ACTIVE=0 means release to Z. SENSE LOW=1 means the column, otherwise pulled high, has a conductive path to the selected low row. Per-key COL→ROW diodes have cathodes toward rows. No analog diode drop or pin current is modeled. `matrixCircuit(size)` reuses row modules and OR trees. `ghostMatrixCircuit()` exposes all possible simple low paths of a diode-free 2×2 matrix as gates. Larger diode-free matrices use equivalent ideal undirected graph connectivity in `senseMatrix`, not a voltage simulator.

`MatrixMachine.sense()` reads the actual isolated gate circuit; the 2×2 diode-free mode also runs its gate circuit. Exhaustive tests compare both with the connectivity model. Matrix size is 2–6 rows and 2–15 columns. Full keyboard views use one UI grid and reused row modules, not a builder per key.

`scanRow()` is the explicit controller software over column signals. It stores one row per step, debounces each position across complete frames, commits modifiers before mapping any key in the frame, and emits transitions. Default debounce requires two matching frames. A held key has no repeat. Pulses shorter than the scan period may be missed. Position codes are `row * columns + column + 1`; they are neither ASCII nor USB usages. Character mapping is a separate US table. Other control keys emit position transitions without characters. The bounded 32-event log drops newest when full and reports the dropped count. Mapping consumes transitions directly, independently of this optional log; acknowledging the log clears only its entries.

US ANSI legends occupy a 6×15 electrical grid, not a physical plate drawing. Empty slots contain no switch. No USB/PS2 protocol or Caps Lock state machine is included. Latched contact controls allow accessible chords. Momentary controls release on pointer up/cancel, key up, blur and hidden documents. No global keyboard listener captures typing from another builder.

Construction levels cover asynchronous capture/request sampling, two-sample filtering with press/release detection, one-hot row selection, parameterized row sensing, small Shift/ASCII mapping, and a real CPU interface. Finite sequences and sampled wide truth tables are labeled as such. Equivalent constructions can pass; reference placement and automatic hints are absent.
