# Manual inputs and configurable counters

`counterComponent(width, mode)` returns a registered, reusable gate module for every integer width 2–8 and mode `up`, `down`, or `up-down`. `counterDemo` wires momentary sources, a numeric display, and Q bit lamps. `counterCircuit` exposes the construction without an identity claim. Each circuit stores exactly `width` flip-flop bits and exposes only Q0 through Q(width−1), least significant first.

Values start at zero and wrap unsigned modulo 2^width. An up/down counter clocks its flip-flops from `INCREMENT OR DECREMENT`; direction logic enables exactly one direction. Both high holds. Releasing either input alone does not count, including when the remaining input stays high. Both must return low to rearm the shared clock. A held input never repeats. This shared-clock contract is deliberate; it is not two independent event queues.

RESET is active high and asynchronous. It wins over counting, clears while COUNT is already high, and holds zero until released. Releasing RESET while COUNT stays high creates no count edge. `Node.resettable` adds pin 2 to a D flip-flop; existing two-pin DFFs, program counters, counter8 blocks, and CPU wiring retain their behavior. Interactive and flattened bit-parallel engines implement the same reset priority. The DFF context menu enables this pin. Expanded diagrams include reset priority on both master and slave latch paths.

The legacy serialized `pulse` source is reused. Default click mode records low → high → low synchronously at the current clock level, preserving a rise and release in timeline history even with simulation paused. The brief button flash is presentation only. A second activation cannot be swallowed by a pending timer. `manualMode: "held"` instead follows pointer or keyboard press/release, ignores repeats, and releases on blur, cancellation, visibility loss, unmount, or runtime reset. Held signals are transient per-builder state; they are not persisted as switch values. Buttons never become toggle switches.

Numeric input4/input8 entry commits on Enter or blur. Only whole unsigned decimal digits within 0–15 or 0–255 are accepted. Blanks, fractions, signs, exponent notation and out-of-range values are rejected without changing bits. Escape restores the current value. Leading zeroes are accepted and normalized. External bit edits update the field. Text and select editing keep native keyboard ownership.

Folding and unfolding ordinary counter modules retain the same nested snapshot, with no state conversion or hidden behavioral counter. Saving stores construction and input mode, following existing builder semantics. Reloading a saved circuit starts runtime count at zero. Runtime timelines, including recorded button edges, are session state.

`COUNTER_LEVELS` supplies 21 optional construction levels, references, conceptual hints and deterministic sequences covering every count value, wrapping, held/falling edges, simultaneous inputs and reset priority. Registered identities display +1, −1 or ±1 according to mode. A built-in identity proves which source implementation is shown. The recognition API does not claim temporal equivalence for arbitrary user constructions; sequence grades are finite evidence, not exhaustive temporal proofs.
